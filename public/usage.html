1. Overview

Mod Tracker LLM is a browser-based, eight-channel sample tracker with Web Audio playback, keyboard pattern editing, and prompt-driven composition. Its channels are kick, snare, hat, openhat, clap, percussion, crash, and bass.

The frontend needs a running application backend that provides /api/samples, /api/health, and /api/compose, plus reachable sample audio URLs. Open the tracker through its running web server—not by opening index.html directly.

2. Quick start

  1. Wait for the sample list and initial preset to load.
  2. Enter a description, such as dusty boom bap hip hop at 90bpm, punchy kick, snappy snare.
  3. Select dolphin or qwen and click COMPOSE, or click PRESET to request the backend’s local template.
  4. Inspect the status and provider/fallback information to see which provider or template supplied the result.
  5. Click PLAY, adjust BPM (tempo) and VOL (master volume), and click STOP when finished.

PRESET skips model generation, not the backend. It still requires the application backend. Your browser may also require a click or keypress before it permits audio playback.

3. Editing and controls

Click a sample to select and audition it, then click a grid cell to position the editing cursor. After typing a prompt, click the grid before using editing shortcuts.

Control reference
Control Action
Sample click Select and audition a sample.
Grid cell click Place the editing cursor.
Arrow keys Move between rows and channels.
Z–M, Q–U Enter notes with tracker-style keyboard mappings; each note advances one row.
Delete / Backspace Clear the selected cell.
Space Toggle playback when focus is outside text inputs and selectors.
PLAY / STOP; BPM / VOL Start or stop playback; adjust tempo and master volume.

Like a piano layout, mapped black-key notes use intervening keys, including S, D, G, H, J, and some number keys.

Each cell shows a note, sample ID, and volume. Sample IDs, volumes, and row numbers are displayed in hexadecimal (base 16): volume 40 means decimal 64. Playback starts from row zero and loops the first pattern.

4. Frontend evaluation

Strengths: The UI clearly separates sample browsing, composition, and editing. Color-coded cell information and sample auditioning help users inspect a beat, while model-provider selection and template fallback reporting make composition choices and outcomes more visible.

Known limitations

  • Only the first pattern is edited and played, despite the song order and pattern fields.
  • The channel count is fixed at eight.
  • No save/export or undo controls are present in the supplied UI.
  • PRESET is not a fully offline mode; it needs the application backend.
  • Shortcut conflict: Number keys 1–8 attempt to select kit samples, but 2, 3, 5, 6, and 7 also enter notes. Clicking the sample list is safer.
  • The header and some status messages are dolphin-specific even when qwen is selected.

5. Troubleshooting

  • No sound? Click PLAY or a sample to unlock browser audio. Check the tracker’s master volume and your system volume, then check for sample-loading errors.
  • Model failure? Check that the selected dolphin or qwen service is available. Try PRESET if the application backend remains available. Composition can return a template fallback, so read the status and provider/fallback information.
  • Unexpected keyboard behavior? Click a grid cell to return to editing and avoid the conflicting numeric sample shortcuts; select samples by clicking instead.
  • Replacing the song? Stop playback before clicking COMPOSE or PRESET.
